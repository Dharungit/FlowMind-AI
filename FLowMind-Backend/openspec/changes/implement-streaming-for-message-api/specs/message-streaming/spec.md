## ADDED Requirements

### Requirement: Stream assistant response MUST deliver tokens incrementally
The server MUST stream assistant response tokens to the client as they are generated by the LLM
Feature: message-streaming

#### Scenario: Successful full stream with new conversation
- **GIVEN** the client sends `POST /v1/stream` with `{"messages": [{"role": "user", "content": "Hello"}]}` and no `conversation_id`
- **WHEN** the server processes the request
- **THEN** the server creates a new conversation
- **AND** the server saves the user message to the database
- **AND** the server returns a `200` response with `content-type: text/event-stream`
- **AND** the first SSE event contains `data: {"conversation_id": "...", "type": "meta"}\n\n`
- **AND** the client receives SSE events containing raw OpenAI chunk JSON (`data: {...}\n\n`)
- **AND** the final event contains `data: {"done": true, "conversation_id": "...", "message": { "id": "...", "role": "assistant", "content": "...", "created_at": "..." }}\n\n`
- **AND** the assistant message is persisted in the database with the full content

#### Scenario: Stream into existing conversation
- **GIVEN** a conversation with ID `conv-123` exists and belongs to the authenticated user
- **WHEN** the client sends `POST /v1/stream` with `{"conversation_id": "conv-123", "messages": [{"role": "user", "content": "Tell me more"}]}`
- **THEN** the server uses the existing conversation
- **AND** the first SSE event contains `data: {"conversation_id": "conv-123", "type": "meta"}\n\n`
- **AND** the assistant response is associated with conversation `conv-123`

#### Scenario: Stream with multiple user messages in one request
- **GIVEN** an authenticated user
- **WHEN** the client sends `POST /v1/stream` with `{"messages": [{"role": "user", "content": "First"}, {"role": "user", "content": "Second"}]}`
- **THEN** all user messages are saved to the database
- **AND** the last user message's content is included in the LLM context
- **AND** the stream proceeds normally

### Requirement: Handle client disconnection gracefully
Rule: If the client disconnects mid-stream, the server MUST save whatever content was accumulated and stop the LLM call

#### Scenario: Client disconnects during active stream
- **GIVEN** the server is actively streaming tokens to the client
- **WHEN** the client closes the connection (e.g., user navigates away, cancels request)
- **THEN** the server detects the disconnect
- **AND** the server aborts the OpenAI API call
- **AND** the server saves the assistant message with the partial content accumulated so far
- **AND** no error is raised

### Requirement: Handle LLM errors during streaming
Rule: If the LLM call fails mid-stream, the server MUST save partial content and notify the client

#### Scenario: OpenAI API error mid-stream
- **GIVEN** the server is actively streaming tokens from OpenAI
- **WHEN** the OpenAI API returns an error or the connection drops
- **THEN** the server saves the assistant message with the partial content accumulated so far
- **AND** the server sends a final SSE event with error details
- **AND** the SSE stream is closed

### Requirement: Authorize stream requests MUST reject unauthenticated users
Only authenticated users SHALL be allowed to call the streaming endpoint

#### Scenario: Unauthenticated request is rejected
- **GIVEN** the client sends `POST /v1/stream` without a valid authentication token
- **WHEN** the server receives the request
- **THEN** the server returns `401 Unauthorized`

#### Scenario: Accessing another user's conversation is rejected
- **GIVEN** conversation `conv-456` belongs to user A
- **WHEN** user B sends `POST /v1/stream` with `{"conversation_id": "conv-456", "messages": [...]}`
- **THEN** the server returns `404 Not Found`
- **AND** no message is saved

### Requirement: Preserve existing non-streaming endpoint
Rule: The existing `POST /v1/conversations/{id}/messages` endpoint MUST continue to work unchanged

#### Scenario: Non-streaming endpoint still functional
- **GIVEN** an authenticated user with an existing conversation
- **WHEN** the client sends `POST /v1/conversations/{id}/messages` with `{"messages": [...]}`
- **THEN** the server returns the full assistant response as JSON (not SSE)
- **AND** the response matches the existing `MessageResponse` schema
